# BeeMemoryBank — Agent Instructions

Self-hosted, end-to-end encrypted knowledge base with a native MCP interface for AI agents.
.NET 10 solution: `libs/` (core logic), `server/` (API + Web), `desktop/` (Windows app + node
orchestrator), `mobile/` (MAUI Android), `tests/`, `tools/`.

Do not edit this file on your own initiative — only when explicitly asked to add or change
something here.

## Build & test

```bash
dotnet build BeeMemoryBank.slnx
dotnet test                          # needs libs/BeeMemoryBank.Core/Embeddings/Models/model.onnx,
                                      # gitignored (~87MB); build.yml downloads it in CI
dotnet run --project server/BeeMemoryBank.Api    # port 5300
dotnet run --project server/BeeMemoryBank.Web    # port 5301, proxies to Api
```

Full setup, project structure, code style, and PR process: see `CONTRIBUTING.md`. This file only
covers what that one doesn't.

## Non-obvious invariants (found the hard way — don't rediscover these)

- **Session lock is global, not per-caller.** `SessionService.IsUnlocked` is one process-wide
  flag shared by the web UI and every MCP agent — there is no per-agent session. An MCP tool
  called while locked (or with a revoked `bee_...` key) fails silently with empty results unless
  it's marked `[RequiresUnlockedSession]` and routed through `McpSessionGuardMiddleware`. Add that
  attribute to any new MCP tool that touches encrypted content.
- **MCP auth identity ≠ "no token".** A `bee_`-prefixed bearer key that doesn't resolve to a
  `tbl_agent` row leaves `ctx.Items["AuthAgent"]` unset entirely — that's distinct from no token
  being presented at all. Code that reasons about auth failures needs to handle both cases.
- **Canonicalize tree paths built from untrusted input.** Any folder/article path derived from
  external data (e.g. import manifests) must go through `TreePathCanonicalizer.Canonicalize` /
  `TryCanonicalize` first. `ArticleService.CreateAsync` does this itself; lower-level primitives
  like `IFolderRepository.EnsureExistsAsync` do NOT — never assume they do.
- **`Process.Kill(entireProcessTree: true)` races on Linux/macOS.** SIGKILL delivery is
  asynchronous there (unlike Windows' near-synchronous `TerminateProcess`), so always follow a
  `Kill()` with a bounded `await proc.WaitForExitAsync(...)`. Skipping this caused three separate
  CI-only test failures before the pattern was applied everywhere it's used.
- **Verify Linux-specific fixes in a real Linux container**, not just local Windows test runs —
  e.g. `docker run --rm -v ${PWD}:/src -w /src mcr.microsoft.com/dotnet/sdk:10.0 ...` matches the
  GitHub Actions `ubuntu-latest` runner closely enough to catch platform-only bugs (apphost
  naming, kill-signal timing) before they ever reach real CI.

## Git remotes

`origin` = private Hetzner server, default branch `master`. `github-remote` = public mirror
(`ultrathinker/BeeMemoryBank`), default branch **`main`**, not `master`. Push to it explicitly
(e.g. `git push github-remote master:main`) — a plain push has created a stray `master` branch
on GitHub before.
